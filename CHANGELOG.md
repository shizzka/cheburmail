# Changelog

Каждая секция начинается с `## <versionName> — <короткий заголовок>`, далее булеты.

## 0.4.6 — Tier 3 polish: производительность и устойчивость
- Индекс на public_key контактов: матчинг по pub_key теперь O(log N) вместо full-scan (миграция v9 → v10)
- SMTP-health сохраняется между рестартами приложения: после OOM-kill повторного retry на упавший SMTP не будет — карантин восстановится
- Snackbar «отправлено через fallback» теперь видно и в открытом чате (раньше только на списке чатов)
- Внутренние улучшения: убран runBlocking при чтении настройки авто-fallback в WorkManager, теперь корректно асинхронно

## 0.4.5 — Новая иконка
- Иконка приложения: красный щит с символом @ на тёмном фоне — данные под защитой. Вместо чебурашки (правовые риски с правообладателем)
- Splash экран теперь тёмный, не белый — без вспышки при запуске

## 0.4.4 — Security hardening round-2
- Re-lock приложения при сворачивании в фон: после возврата нужно снова ввести PIN (раньше один разлок открывал приложение до перезагрузки)
- DELETE-команды по сети теперь требуют авторизации: только автор сообщения в том же чате может удалить своё сообщение
- MEMBER_REMOVED в групповых чатах требует admin'а; legacy-группы (без admin metadata) полностью отвергают remote-remove (защита от удалённого DoS)
- Alias-аккаунты для admin-команд: если админ ответил approve/reject/MEMBER_REMOVED через свой второй аккаунт (после fallback), получатель корректно распознаёт его как admin'а
- ImapClient stuck-fetch detection: если IMAP-fetch завис на >90 сек, поток принудительно прерывается, чтобы не блокировать новые синхронизации
- App-lock PIN теперь PBKDF2 + соль + throttling (после 5 неудач — 5 минут lockout с экспоненциальным backoff). Старый PIN мигрируется автоматически
- Сохранение файлов: имя файла из расшифрованной metadata теперь sanitize'ится (защита от path-injection)
- 84 регрессионных тестов добавлено для security-фиксов

## 0.4.1 — Security hardening
- Авторизация на DELETE: и MEMBER_REMOVED — теперь чужой контакт не может стирать ваши сообщения или выкидывать вас из группы
- PIN-код теперь PBKDF2 + соль + throttling (5 неудач → блок на 5 минут, экспоненциальный backoff)
- Защита от скриншотов включена по умолчанию
- Безопасное сохранение файлов (защита от path-injection в именах)
- OutboxDrainWorker больше не теряет сообщения молча — помечает FAILED
- Tags релизов immutable, в release notes добавлен SHA-256 артефакта
- Прозрачно мигрирует старый PIN-хеш на новый формат при первом успешном вводе
- Auto-cleanup plaintext-backup от старой SQLCipher-миграции на каждом старте
- Subject-only Delivery ACK игнорируется (был forgeable)

## 0.4.0 — Multi-email identity и авто-fallback
- Поддержка нескольких email-аккаунтов одной identity. Получатель распознаёт вас по pub_key, даже если вы пишете с алиаса
- Авто-fallback при блокировке SMTP: если smtp.mail.ru заблокирован TSPU, отправка автоматически идёт через ваш yandex/rambler
- Добавлен Rambler как третий провайдер (независимая инфраструктура)
- Новый экран «Диагностика сети» в Настройках — проверяет SMTP/IMAP/HTTPS ко всем провайдерам, говорит конкретный диагноз вроде «TSPU режет SMTP mail.ru»
- Health-индикатор у каждого аккаунта (зелёная/красная точка) + текст карантина
- Snackbar при fallback: «Отправлено через yandex (mail.ru заблокирован)»
- ContactDetail показывает все алиасы контакта
- QR-код несёт список ваших алиасов — собеседник узнаёт о них автоматически
