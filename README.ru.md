# CheburMail

**Мессенджер со сквозным шифрованием для Android, работающий поверх обычной электронной почты.**

Никаких своих серверов. Не нужен номер телефона. Сообщения идут через стандартный IMAP/SMTP (Яндекс Почта, Mail.ru, Rambler), но почтовый провайдер видит только метаданные — никогда содержимое.

## Почему CheburMail, а не Signal / Telegram / WhatsApp?

| | CheburMail | Signal | Telegram | WhatsApp |
|---|---|---|---|---|
| **Работает в РФ без VPN** | Да — Яндекс/Mail.ru/Rambler в белых списках | Заблокирован с 2024, нужен VPN | Частично заблокирован, нестабилен | Работает, но серверы Meta могут заблокировать |
| **Переживёт «чебурнет»** | Да — почта это внутренняя инфраструктура | Нет — зависит от зарубежных серверов | Нет — серверы за рубежом | Нет — серверы за рубежом |
| **Переживает точечную блокировку SMTP** | Да — авто-fallback между вашими аккаунтами (например, SMTP Mail.ru заблокирован → приложение незаметно отправляет через Яндекс) | N/A | N/A | N/A |
| **Нужен номер телефона** | Нет — только почтовый аккаунт | Да | Да | Да |
| **Свои серверы** | Нет — работает поверх почты | Серверы Signal Foundation | Серверы Telegram | Серверы Meta |
| **Сквозное шифрование** | Да (X25519 + XSalsa20-Poly1305) | Да (Signal Protocol) | Только «секретные чаты» | Да (Signal Protocol) |
| **Открытый код** | Да | Да | Только клиент | Нет |
| **Можно заблокировать одним доменом** | Нет — работает через любого российского почтовика | Да | Да | Да |

**Суть**: Яндекс Почта, Mail.ru и Rambler — часть утверждённой коммуникационной инфраструктуры страны. Их заблокируют последними — если вообще когда-нибудь. CheburMail использует их как транспорт, шифруя всё на стороне клиента. Провайдер видит кто с кем переписывается, но не содержимое.

**«Чебурнет»** — разговорное название суверенного интернета, при котором зарубежные сервисы отключены. В этом сценарии Signal мёртв, Telegram нестабилен, а **почта работает**. CheburMail создан для этого сценария.

## Как это работает

CheburMail превращает ваши почтовые ящики в защищённый канал связи:

1. **Входите** под своей Яндекс / Mail.ru / Rambler почтой (пароль приложения)
2. **(Опционально) добавляете второй аккаунт** — даёт авто-fallback, если SMTP одного из провайдеров заблокируют
3. **Обмениваетесь ключами** — сканируете QR-код при личной встрече; QR несёт сразу все ваши алиасы
4. **Сообщения шифруются** на устройстве перед отправкой — провайдер видит только набор символов
5. **Доставка через IMAP/SMTP** — без промежуточных серверов, без регистрации

```
Вы (шифрование) → SMTP → Почтовый провайдер → IMAP → Получатель (расшифровка)
                          ↑ видит только метаданные
```

Если SMTP одного из ваших аккаунтов заблокируют на уровне оператора (TSPU делает это точечно для конкретных сервисов), CheburMail обнаруживает фейл и **молча перепосылает через ваш второй аккаунт**, незаметно для вас. Получатель распознаёт вас по публичному ключу независимо от того, с какого алиаса вы отправили.

## Безопасность

| Слой | Технология |
|------|-----------|
| Обмен ключами | X25519 (Curve25519 Diffie-Hellman) |
| Шифрование | XSalsa20-Poly1305 (с аутентификацией) |
| Хранение ключей | Android Keystore + Tink AEAD |
| Локальная БД | SQLCipher (AES-256), passphrase в зашифрованном DataStore |
| Реализация | libsodium через lazysodium-android |
| Медиа | Шифрование каждого файла отдельным ключом |
| App-lock | PBKDF2WithHmacSHA256 (200k итераций) + соль на установку + lockout-throttling |

- **Zero-knowledge**: почтовый провайдер не может прочитать ваши сообщения
- **Никаких своих серверов**: нечего ломать, отключать или забирать по запросу
- **Шифрование at-rest**: контакты, чаты, сообщения, фингерпринты — всё в SQLCipher-БД; украденное или с root-доступом устройство не сможет прочитать БД без app-bound passphrase
- **Уникальный nonce** для каждого сообщения
- **Верификация**: сравнение фингерпринтов через QR-код или вручную 60-значный safety number
- **Авторизация управляющих сообщений**: remote DELETE принимается только от автора в том же чате; групповой MEMBER_REMOVED — только от верифицированного админа (с учётом алиасов)
- **App-lock relock-on-background**: при сворачивании приложения на возврате снова требуется PIN
- **Защита от скриншотов** в чатах (включена по умолчанию)
- **Никаких subject-only delivery receipts** — они подделываемы, намеренно не реализованы

## Возможности

### Работает
- **1-на-1 чаты** с E2E шифрованием
- **Групповые чаты** с E2E шифрованием (fan-out: каждому участнику свой шифротекст, без общего ключа)
- **Approval-флоу для добавления в группу** — не-админский add идёт через очередь подтверждения, админ сверяет fingerprint перед отправкой инвайта
- **Multi-email identity** — одна криптографическая identity, несколько email-адресов (Яндекс + Mail.ru + Rambler). Получатель распознаёт вас по публичному ключу, не по email
- **Авто-fallback при блокировке SMTP** — если ваш основной SMTP отрезан TSPU/оператором, приложение молча перепосылает через ваш второй аккаунт; вы видите snackbar `«Отправлено через yandex (mail.ru заблокирован)»`
- **Per-account SMTP-health трекинг** — упавшие аккаунты помещаются в карантин с экспоненциальным backoff (5 мин → 1 ч cap), состояние переживает рестарт приложения
- **Экран диагностики сети** — DNS + TCP пробы SMTP/IMAP/HTTPS ко всем провайдерам, выдаёт конкретные диагнозы вроде «TSPU режет SMTP Mail.ru — используйте Yandex или VPN»
- **Медиа-сообщения**: фото, файлы, голосовые — всё зашифровано
- **Обмен ключами через QR-код** — сканирование при личной встрече, без серверов; QR несёт сразу все ваши алиасы
- **Ручной обмен ключами без QR** — короткий код, если сканирование невозможно
- **Верификация фингерпринта** — 60-значный safety number (QR или вручную)
- **Автоматический re-keyex после переустановки** — приложение замечает что собеседник потерял ключи и обмен повторяется автоматически с защитой от спама (`ReactiveKeyexGate`)
- **Reply, цитирование, авторизованное удаление** сообщений (удалять может только автор, удаление и из IMAP)
- **Переименование чатов**
- **Фоновая синхронизация** через WorkManager + IMAP IDLE
- **Защита от зависшего IMAP-fetch** — если fetch висит >90 сек, его поток принудительно прерывается, чтобы не блокировать новые синхронизации
- **PIN / биометрия** на вход с PBKDF2-производным хешем, солью, и защитой от перебора (5 неудач → 5 мин блок, экспоненциальный backoff)
- **Re-lock при сворачивании** — выход из приложения по любой причине требует повторного ввода PIN на возврате
- **Защита от скриншотов** в чатах (включена по умолчанию)
- **Диалог «Что нового»** при первом запуске после обновления
- **Зашифрованная локальная БД** (SQLCipher) с прозрачной миграцией со старых plaintext-установок
- **Автоочистка IMAP** — автоматическое удаление обработанных писем старше 7 дней
- **Проверка обновлений** — уведомление при выходе новой версии (отдельные debug / release каналы)
- **Без трекинга, аналитики и рекламы**

### В разработке
- **UI-восстановление** для участников группы, переустановивших приложение
- **Tombstones для удалённых групп** — чтобы архивная IMAP-почта не воскресила удалённый чат

### Намеренно не реализовано
- **Delivery / read receipts** и **исчезающие сообщения** — обе фичи требуют дополнительный control-message трафик через IMAP/SMTP на каждое отправленное сообщение, что прямо противоречит цели CheburMail (минимальный footprint у провайдера, маленькая поверхность метаданных). Не будут реализованы.

## Поддерживаемые провайдеры

| Провайдер | IMAP | SMTP | Примечания |
|-----------|------|------|-----------|
| Яндекс Почта | `imap.yandex.ru:993` | `smtp.yandex.ru:465` | Нужен пароль приложения |
| Mail.ru | `imap.mail.ru:993` | `smtp.mail.ru:465` | Нужен пароль приложения; покрывает `@mail.ru`, `@bk.ru`, `@list.ru`, `@inbox.ru` (одни сервера) |
| Rambler | `imap.rambler.ru:993` | `smtp.rambler.ru:465` | Обычный пароль аккаунта (Rambler не имеет отдельных паролей приложений); независимая от Яндекс/Mail.ru инфраструктура |

> Для Яндекс/Mail.ru нужно сгенерировать **пароль приложения** в настройках безопасности почты. CheburMail никогда не видит ваш реальный пароль. Для Rambler используется обычный пароль аккаунта (предварительно включите доступ по IMAP/SMTP в настройках безопасности).

**Совет**: добавить два провайдера (например, Яндекс + Mail.ru) **очень рекомендуется** — даёт авто-fallback на случай точечной блокировки SMTP одного из них.

## Сборка из исходников

**Требования**: JDK 17, Android SDK (API 35)

```bash
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk-17

git clone https://github.com/shizzka/cheburmail.git
cd cheburmail
./gradlew assembleDebug --no-daemon
# APK → app/build/outputs/apk/debug/app-debug.apk
```

Для release-сборки задайте env-переменные `CHEBURMAIL_STORE_PASSWORD` / `CHEBURMAIL_KEY_PASSWORD` или создайте `keystore.properties` в корне репо (gitignored) с ключами `storePassword` / `keyPassword`.

## Стек технологий

- **Язык**: Kotlin
- **UI**: Jetpack Compose + Material 3
- **Crypto**: lazysodium-android (libsodium) + Google Tink
- **Транспорт**: JavaMail (IMAP/SMTP)
- **Хранение**: Room поверх SQLCipher + Encrypted DataStore
- **Sync**: WorkManager + IMAP IDLE foreground service
- **QR**: ZXing (генерация) + Google Code Scanner (сканирование)
- **Min SDK**: 26 (Android 8.0)

## Формат email

Сообщения используют свой формат, невидимый для обычных почтовых клиентов:

- **Subject**: `CM/1/<chatId>/<messageUuid>`
- **Body**: `Base64(nonce || ciphertext)`
- **Content-Type**: `application/x-cheburmail`

## FAQ

**Почему почта?**
Почта — федеративная, проверенная временем инфраструктура, которая уже существует везде. Не нужно поддерживать серверы, нет затрат на инфраструктуру, нет single point of failure.

**Может ли почтовый провайдер прочитать мои сообщения?**
Нет. Сообщения шифруются на устройстве перед отправкой на почтовый сервер. Провайдер видит отправителя, получателя и время — но содержимое неотличимо от случайных данных.

**Что если я потеряю устройство?**
Вы потеряете сообщения и ключи. Это by design — нет бэкапа, нет server-side recovery, нет способа извлечь ваши ключи. Если кто-то украдёт телефон, контактам нужно просто заново обменяться ключами с вашим новым устройством; локальная БД зашифрована SQLCipher, поэтому вор не сможет прочитать чаты даже с root.

**Что если SMTP заблокируют пока я отправляю?**
Если у вас настроен второй email-аккаунт, приложение незаметно перепосылает через него и показывает snackbar с уведомлением о fallback. Если только один аккаунт настроен — сообщение попадает в очередь и retry'ится с экспоненциальным backoff. Экран Диагностики (Настройки → Сеть) покажет конкретно какие сервера сейчас доступны.

**Что если кого-то добавили в групповой чат без моего одобрения?**
Не получится. Только админы группы могут добавлять новых участников. Когда не-админ пытается добавить кого-то, админ видит запрос с фингерпринтом нового участника и должен явно подтвердить перед отправкой инвайта в группу.

**Можно ли использовать Gmail / Outlook?**
Пока нет, и в РФ скорее всего не имеет смысла — TSPU блокирует SMTP зарубежных почтовиков. Технически добавить Gmail/Outlook несложно (PR welcome), но они не релевантны для сценария «Чебурнета», под который CheburMail и спроектирован.
